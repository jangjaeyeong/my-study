자바의 특징
	1. 객체지향 프로그래밍
		객체지향 프로그래밍은 프로그램을 객체 단위로 쪼개고 이 객체들을 조립하는 방식으로 사용합니다
		절차지향 프로그래밍 언어에서도 함수 단위로 쪼갤수는 있지만 각각의 독립적인 인스턴스로 만들 수 없고, 함수의 실행이 끝나면 가지고있던 값을 모두 잃기 때문에 매번 매개변수로 
		데이터를 던져줘야 합니다.(스택 메모리에서 증발) 반면에 객체 지향 프로그래밍은 클래스를 각각 독립적인 인스턴스로 만들어 데이터를 힙 메모리에 저장해 데이터가 날아가지 않기에
		관리가 더 편리해집니다.

	2. JVM
		자바는 Java Virtual Machine이라는 가상의 환경 위에서 동작하기 떄문에 OS나 설정의 환경에서부터 수정 과정을 거치지 않고 실행하는 데에 자유롭습니다.

	3. Garbage Collection
		GC라고 부르는 Garbage Collection이 알아서 사용하지 않는 메모리를 정리해줍니다. C/C++은 개발자가 직접 메모리를 할당하고 해제해야 하는 번거로움이 있지만 
		그 역할을 GC가 대신 해주기 때문에 상대적으로 메모리 할당/해제 과정에서부터 자유로워 다른 부분에 더 집중할 수 있습니다.

	4. 정적 타입 언어
		변수를 선언할 때 자료형을 지정해주기 떄문에 해당 변수가 어떤 자료형인지 파악하기 쉽고 컴파일 단계에서 오류를 잡아낼 수 있습니다.
		파이썬의 경우 자료형 선언을 하지 않기 떄문에 초반에는 편하지만 프로그램이 커질수록 해당 변수가 어떤 자료형인지 알기 어렵고, 자료형을 선언하지 않는다는 문제 때문에 
		일단 실행은 되지만 작동을 하는 과정에서 에러가 날 수 있다는 단점이 있습니다.

자바의 장점
	1. 풍부한 커뮤니티
		자바라는 언어가 수십년간 인기를 받아왔기에 문제가 생겼을 때 검색으로 해결책을 찾기 가장쉬운 언어 중 하나입니다.

	2. 높은 안정성과 보안성
		수십년간 많은 기업들에서 사용하며 검증되었기 때문에 대규모 시스템을 구축하는 데 최적화 되어있습니다.

	3. 캡슐화, 다형성, 상속
		객체지향은 데이터를 객체 안에 숨겨두고 (private) 특정 메서드로만 접근하게 만들어 직접적으로 데이터를 수정할 수 없게 만드는 캡슐화와
		하나의 역할에 여러 가지 구현체를 끼워 넣어 코드 수정 최소화와 유연성을 만들어주는 다형성,
		비슷한 특징을 가진 객체들이 있다면 공통된 부분만 뽑아 부모 클래스로 만들고 상속을 받아 자식 클래스에서 부모 클래스의 함수를 가져다 쓰거나, 부모 클래스의 함수를 재정의해서 
		사용할 수 있는 재사용성을 크게 올려줍니다.

자바의 단점
	1. 상대적으로 느린 실행 속도
		코드가 바로 실행되는 것이 아닌 JVM을 거치는 과정이 필요하므로 C/C++ 같은 언어에 비해 실행 속도가 느립니다.

	2.  높은 메모리 사용량
		JVM 자체를 띄워야 하고 GC가 백그라운드에서 항시 돌아가기 때문에 C/C++, 파이썬에 비해 시스템 메모리 소모가 큰 편입니다.
	
	3. 장황한 코드
		단순한 기능을 구현할 때도 다른 언어들보다 작성해야 하는 코드가 많아 무겁게 느껴집니다.
		C/C++의 경우 scanf("%c",&ch) 로 입력받는 코드가 완성되지만 자바의 경우 Scanner sc = new Scanner(System.in); ch = sc.next().charAt(0); 처럼 상대적으로 코드의 길이가 길어집니다.
		코딩테스트 문제의 제출 라인을 볼 때 파이썬은 300~500 라인인 반면 자바는 700~900 라인으로 차이가 많이 나는 것을 볼 수 있습니다.
